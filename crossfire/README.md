# Crossfire — Multiplayer Arena

A browser-based 3D free-for-all shooter built with Three.js, React, Vinext, and Cloudflare D1.

## Play

Enter a callsign and choose **Quick Play** to enter the shared public matchmaking room, or **Create Room** and copy the invite link. Friends open the link and enter the same six-character code. **Warm up against bots** creates a separate practice match with three clearly labelled opponents.

Each room supports eight total players. First to 15 kills wins; rounds last five minutes and restart automatically. Eliminated players respawn after three seconds. Players are protected until they first enter the arena, and briefly after spawning.

| Control | Action |
| --- | --- |
| WASD | Move |
| Mouse | Look |
| Left click | Shoot |
| Right click | Aim down sights |
| Space | Jump |
| Shift | Sprint |
| R | Reload |
| 1 / 2 / 3 | Assault rifle / shotgun / marksman rifle |
| Tab | Scoreboard |
| Esc | Menu |

A desktop keyboard and mouse are required for gameplay. The lobby adapts to small screens. When an embedded browser denies mouse capture, hold the right mouse button and drag to look around.

## Local setup

Use Node.js 22.13 or newer (Node.js 24+ is recommended for native TypeScript tests).

```sh
npm ci
npm run build
npm run db:local
npm run dev
```

Open the local URL printed by the server, normally http://localhost:5173. Apply `db:local` once to a fresh local database; do not replay it after successful initialization. Database state lives in ignored `.wrangler/state`.

A friend on another computer needs a reachable deployment of the same server. `localhost` points to each person's own computer.

## Verification

```sh
npm test
npx tsc --noEmit
npm run build
```

With the dev server running, `npm run test:multiplayer` creates two independent sessions and verifies shared membership, authentication, actual PvP damage, replicated kills and deaths, respawn, and weapon changes. Set `CROSSFIRE_URL` to test another accessible server. The test removes its sessions afterward.

## Multiplayer design

`lib/game.ts` contains the shared movement and collision model and the authoritative combat simulation. `/api/game` creates rooms, authenticates per-player session tokens, and exchanges input and snapshots. The server controls player speed, collision, ammunition, weapon cooldowns, reloads, hits, spawn protection, scoring, and respawns. Tokens are removed from public snapshots.

D1 stores each room with a version counter. Compare-and-swap updates retry concurrent requests, so rooms work across server instances. Clients exchange input about every 110 ms, predict local movement, and interpolate remote players. This HTTP transport is intended for a small casual arena; it has more latency than a dedicated WebSocket game server. Real network and server latency are shown in the HUD. Stale sessions expire after 18 seconds and abandoned rooms are cleaned up after 30 minutes when a room is created.

Room invitations use the URL fragment. No third-party networking or hosted asset service is required. All geometry, weapon models, textures, and audio are generated by the application.

## Hosting

### Vercel

Import `Mdev-7/gaming` into Vercel and set **Root Directory** to `crossfire` and **Framework Preset** to `Next.js`. Leave the install, build, and output settings on their defaults; `vercel.json` selects `npm ci`, `npm run build:vercel`, and `.next`. Remove an old `dist` output override if you added one.

Vercel uses a native Next.js build so `.next/routes-manifest.json` is generated. `npm run build` also selects Next.js automatically when Vercel sets `VERCEL=1`. Local and Sites builds continue to use Vinext.

The Vercel site forwards `/api/game` to the existing public Crossfire game server, which owns the shared Cloudflare D1 room state. It does not create an in-memory multiplayer server inside Vercel functions. The existing game server must remain online and public. To use a different compatible backend, set the server-only Vercel environment variable `CROSSFIRE_GAME_SERVER_URL` to its origin and redeploy; never set it to the Vercel site's own URL.

To test this deployment path locally:

```sh
npm run build:vercel
npm run start:vercel
```

The Next.js site defaults to port 3000. With it running, `CROSSFIRE_URL=http://localhost:3000 npm run test:multiplayer` checks the full frontend API proxy and live game server.

### Sites / Cloudflare

`.openai/hosting.json` retains this game's Sites project ID and declares the `DB` binding. The Sites build integration outputs the Cloudflare Worker and client assets in `dist/`. Deployment applies the tracked schema migration under `drizzle/`.

Sites access is separate from in-game room codes. A private publication only allows approved visitors. Public link access must be enabled before friends can join the hosted game without an invitation to the Site.
